# 五张朏朏：全量连续浅浮雕

**人只需看** `http://localhost:8121/relief.html`，顶部切换角色。每张保留“原分离／静态曲面／动态曲面”三态；±46°、暂停与相位控制可直接检查。

## 本次完成

力士3组件；妙音鸟5；岩画5；螭吻5；角端（现有目录名角盔）5，共23组件。没有改名搬动原始资产，没有重画或补画。五张原图 SHA256、所有切片可见 RGBA 和透明度逐像素校验不变。

统一使用 `site/ar/feifei-surface.js`：共享高度场、固定接缝、内部隆起、每帧重算法线，再经过 Three.js 的 normalMatrix。`miaoyinniao-relief.js` 只保留兼容导出，不维持另一套算法。

- 原高度80mm，宽度按各自原稿比例；96×128细分，每角色12513顶点、24576三角形的共享基础网格。组件重复引用，不是每片任意拉开。
- 总深度实际0～2.788235mm，GPU强制0～3mm；所有切缝静态/呼吸深度为0。
- 身体峰值2.5mm、呼吸±0.28mm；翅膀/披风峰值1.3mm、呼吸±0.10mm；独立道具、握管手、头饰与地面不呼吸。
- 材质与灯光保持妙音鸟已验收设置：Standard、roughness=1、metalness=0、固定弱平行光与环境补光。无雾、无粒子、无新美术。
- 角色纸面X=34.75mm、脚底Z=35mm，最前边界X≥31.961765mm，仍在管身远侧；卡4/5合同172.8mm宽、X=55mm记录在每套state中。
- 每秒硬切、五站位、五帧循环仅记录状态合同。本轮不修改线上轮播、线上卡尺寸或现有试管遮挡体，不冒称已做完真机接入。

## 机器数据：人不必逐个打开

入口 `surfaces.json` 指向每个角色的 `surface/state.json`。

每个角色的 `surface/` 包含：

| 文件 | 用途 |
|---|---|
| `state.json` | 尺寸、锚点、组件映射、三态、轮播站位、物理范围 |
| `mesh.json` | 实际BufferGeometry顶点、UV、法线基底与索引；可用BufferGeometryLoader读取 |
| `control.rgba8` | 静态深度和呼吸权重；GPU动态法线从同一高度场求导 |
| `ownership.u8` | 原分辨率互斥像素归属；避免切片透明边缘重复混合 |
| `source-verification.json` | 原画、切片、透明度未变的检查 |
| `gpu-verification.json` | 此套实际15组WebGL渲染测试及呼吸帧差 |
| `comparison.png` | 46°三态实渲染截图，供人快速看 |

二进制数组按从下到上的行顺序，字段和尺寸在state中写明。预览直接读取这些导出网格和控制文件，**不是另写一份只供演示的模型**。

## 已验证与未声称

5角色 × 5角度（−46/−30/0/30/46°）× 3呼吸相位，共75组；组件渲染与同一连续参考面逐通道差异均0。每张都检测到呼吸两端真实帧差。详情见 `surface-verification.json`。52项单元/回归测试通过。

这是桌面WebGL机制与资产的验收，不替代手机GPU性能、30cm下的主观动效强度、真实试管遮挡及追踪验收。原画背部不可见信息没有重建。身体分区包含的头部等区域也可能有微动，不宣称已经具备胸腹解剖级绑定。

## 可复现

1. `python tools/prepare-feifei-ownership.py`：从现有ORA恢复缺失导出、校验原像素、生成归属数据。
2. `node tools/build-feifei-surfaces.mjs`：同一算法生成全部网格、控制场和状态。
3. `node tools/serve-feifei-layers.mjs`：打开上述检查页，逐角色运行接缝检查并保存对比图。
4. `node tools/verify-feifei-surfaces.mjs`：检查渲染证据与当前控制场哈希一致，生成汇总。
5. `node --test tests/*.test.mjs`：全量回归。
